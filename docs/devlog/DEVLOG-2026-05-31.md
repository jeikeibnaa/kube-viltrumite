## Errors Hit

**`make manifests` / `make install` fail on Windows with Git Bash**:
`$(shell go env GOPATH)` expands to `C:\Users\hulge\go`; Git Bash's `/usr/bin/sh` strips the backslash after `C:` and fails to find the binary. Workaround: pass `CONTROLLER_GEN=$(cygpath -u $(go env GOPATH))/bin/controller-gen` on the make invocation. Permanent fix needed in Makefile (see Key Decisions).

**`controller-gen paths="./api/..."` fails with "no Go files in api/"**:
Root `api/` directory contains no `.go` files (only `api/v1alpha1/` does). Despite `...` being recursive, controller-gen reports the parent package as an error. Workaround: use `./api/v1alpha1/...` directly.

**Operator startup failed with `unable to load knowledge base`**:
Default path `/etc/viltrumite/knowledge` does not exist on the dev machine. Fix: pass `--knowledge-base-path` flag pointing to `knowledge/tools/` in the repo root.

**`helm` not on PATH**:
WinGet installs Helm but the PATH modification only takes effect in a new shell. Worked around by using the full WinGet package path for the session.

2. **`controller-gen` path workaround vs. Makefile fix** — chose workaround for this session rather than modifying the Makefile mid-session. The correct fix is to replace `$(shell go env GOPATH)` with `$(shell cygpath -u '$(shell go env GOPATH)')` in Makefile line 3, or simply use `CONTROLLER_GEN := controller-gen` and rely on `PATH` after installation.

3. **`make manifests` path** — `./api/...` fails on this repo's layout; `./api/v1alpha1/...` is the correct target. Consider updating the Makefile or adding a `.go` package declaration stub to `api/` root.
