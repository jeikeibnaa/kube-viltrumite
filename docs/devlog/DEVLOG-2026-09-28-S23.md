| `aliases` | other names scanners report (Helm chart names); a name belongs to one tool only |

**Sources.** GitHub release pages (argo-cd, cert-manager, external-secrets, vault-helm,
kube-prometheus-stack chart) and istio.io release announcements. All 31 URLs returned HTTP 200.
The entries' breaking changes are not yet checked against them (S26).

**Semver.** `CompareVersions(a, b) (int, error)` uses `github.com/Masterminds/semver/v3`, the
library Helm uses. A `v`/`V` prefix, surrounding spaces and partial versions (`1.14` = `1.14.0`)
are accepted; patches, pre-releases and double-digit minors order correctly (`0.9.0 < 0.9.5`,
`1.9.0 < 1.10.0`, `1.14.0-rc.1 < 1.14.0`). `normalizeVersion` now returns full semver
(`v1.14` → `1.14.0`) and leaves unparsable input unchanged.

- `LatestSafeVersion` compares full versions, so external-secrets `0.10.0` now sees `0.10.5`
  (audit #6). An unparsable installed version (`latest`) returns `found=false`.
- `Resolve` returns the exact entry or the latest one below the target on the same minor line:
  external-secrets `0.9.5` resolves to the low-risk `0.9.5` entry (it used to resolve to the
  high-risk `0.9.0` one), `0.9.7` → `0.9.5`, cert-manager `v1.14.3` → `1.14.0`, vault `1.15.3` →
  `1.15.2`. A target with no covering entry, or one that does not parse, is an error.

**Validation in `Load`.** YAML is decoded with `KnownFields(true)` (a schema v1 `version:` key or a
typo is an error) and a second YAML document is rejected. Each file is checked: `tool` and alias
names; at least one version; `app_version` present, parseable, strictly ascending; `chart_version`
parseable and ascending when set; `source` an absolute http(s) URL; `min_kubernetes` present and
parseable; `risk_level` in `low|medium|high|blocking`; `upgrade_notes` present; breaking changes
have a description and a type in the enum; `incompatible_with` values parse. Then across files:
names and aliases unique, and every `incompatible_with` key is a known tool or alias. All problems
come back at once through `errors.Join`, each prefixed with the file. A file that parses but fails
validation still registers its names, so it does not cause false "unknown tool" errors elsewhere.

**Validation test.** `TestKnowledgeBase` loads the embedded files (all rules above) and adds the
conventions of the shipped data: the file is `<tool>.yaml`, `app_version` is written canonically,
every entry has a `chart_version` and an `https` source. `TestLoad_Validation` (28 cases) shows each
rule firing on a fixture.

**Data changes needed by the rules.** `ingress-nginx` has no KB entry, so its `incompatible_with`
lists were removed, six of them non-empty (cert-manager 1.12/1.13/1.15, argo-cd 2.7/2.8/2.12). Four
of those were already described in `upgrade_notes`; notes were added for cert-manager 1.13 (avoid 1.4.0) and
argo-cd 2.7 (avoid 1.5.0). external-secrets 0.10.0's `vault: ["0.24.0"]` was a chart version and is
now `1.13.1`, the Vault app version that chart ships.

### Key Decisions
1. **`app_version` is the compare key; `chart_version` rides along.** Raw installs (image tag),
   Helm (`Chart.Metadata.AppVersion`) and Flux v2 (`status.history[].appVersion`) can all report
   the app version; only Argo CD sees just the chart version, and `chart_version` lets S24 map it.
   The executor needs the chart version (S27), so `Resolve(...).ChartVersion` provides it.
2. **Masterminds/semver/v3 instead of a hand-written parser.** It is the library Helm compares chart
   versions with, it is already linked through Helm, and its constraints are available for S28/S31.
3. **Validation lives in `Load`, not only in a test.** A `--knowledge-base-path` override gets the
   same checks at startup. Before this, an unknown `risk_level` such as a typo was scored as LOW
   (`riskOrder`'s zero value), which is unsafe for autoplan.
4. **Strict YAML.** `KnownFields(true)` and one document per file: a v1 file or a typo fails loudly
   instead of loading empty entries.
5. **An entry covers the patches after it on its minor line.** `Resolve` picks the exact entry or
   the latest one below the target on the same `major.minor`; a later minor with no entry is
   unknown, not silently mapped to the last entry.
6. **No recommendation from an unparsable installed version.** `found=false` is safer than
   treating `latest` as older than everything.
7. **Names match exactly** (lowercase DNS labels enforced in the KB). No case folding, so what the
   KB declares is what matches.
8. **`ingress-nginx` constraints became prose.** The requested rule (keys must be known tools or
   aliases) catches typos, and ingress-nginx is not tracked. The facts stay in `upgrade_notes`;
   S26 decides whether ingress-nginx gets a KB entry.
9. **Mappings from upstream, not memory.** Chart↔app versions came from chart indexes and
   `Chart.yaml` files, and every `source` URL was checked. The rest of the data is still unverified
   (S26).
10. **Shipped-data conventions only in `TestKnowledgeBase`.** A custom KB may leave `chart_version`
    empty (a tool with no Helm chart) or write `v1.2`; the embedded one may not.
11. **One commit** for loader, data and tests: the strict loader rejects v1 files and the v1 loader
    cannot read v2, so no split leaves a green tree.

| `aliases` | scanner-уудын мэдээлдэг бусад нэр (Helm chart-ийн нэр); нэг нэр зөвхөн нэг хэрэгсэлд хамаарна |
| `detection` | өөрчлөгдөөгүй (raw суулгалтыг тааруулах) |
| `versions[].app_version` | upstream app хувилбар, `v`-гүй бүтэн semver; харьцуулах түлхүүр |
| `versions[].chart_version` | тухайн app-ийг агуулсан Helm chart-ийн хувилбар, repo-д нийтэлсэн хэлбэрээрээ |
| `versions[].source` | release notes-ийн URL |
| `min_kubernetes`, `incompatible_with`, `breaking_changes`, `risk_level`, `upgrade_notes` | өмнөх шигээ; `risk_level` нь `blocking`-ийг бас зөвшөөрнө; `incompatible_with`-ийн түлхүүр alias байж болох ба утгууд нь app хувилбарууд |

Entry нь өөрийн хувилбар болон дараагийн entry хүртэлх ижил `major.minor` шугам дээрх хожмын
patch-уудыг хамардаг.

**Alias-ууд.** `kube-prometheus-stack` → `prometheus-stack`; `istiod`, `base` → `istio`;
`argocd` → `argo-cd`. `Matrix.CanonicalName(name)` нь нэр эсвэл alias-ыг хэрэгсэл рүү буулгадаг ба
`LatestSafeVersion`, `LatestVersion`, `Resolve` нь alias хүлээн авдаг.

**App болон chart хувилбарууд** (upstream chart-уудаас уншсан бодит харгалзаа): дээрх англи хэсгийн
хүснэгтийг үзнэ үү. Товчоор: argo-cd 2.7.0 … 2.12.0 ↔ chart 5.30.0 … 7.4.0 (тухайн app-ийг агуулсан
анхны argo-helm chart); cert-manager 1.12.0 … 1.15.0 (`"1.12"` … `"1.15"` байсан) ↔ `v1.12.0` …
`v1.15.0`; external-secrets, istio-д chart ба app хувилбар ижил; prometheus-stack-ийн app хувилбар
нь prometheus-operator-ийн 0.63.0 … 0.76.0 ↔ chart 45.0.0 … 62.0.0; vault 1.13.1 … 1.16.1 ↔ chart

kube-prometheus-stack chart) болон istio.io-ийн release зарлалууд. 31 URL бүгд HTTP 200 буцаасан.
Entry-үүдийн breaking change-үүдийг эдгээртэй хараахан тулгаагүй (S26).

**Semver.** `CompareVersions(a, b) (int, error)` нь Helm-ийн ашигладаг `github.com/Masterminds/semver/v3`
санг хэрэглэдэг. `v`/`V` угтвар, хоосон зай, дутуу хувилбар (`1.14` = `1.14.0`) хүлээн авагдана;
patch, pre-release, хоёр оронтой minor зөв эрэмбэлэгдэнэ (`0.9.0 < 0.9.5`, `1.9.0 < 1.10.0`,

1. **Харьцуулах түлхүүр нь `app_version`; `chart_version` хамт явна.** Raw суулгалт (image tag), Helm

   өгнө.
