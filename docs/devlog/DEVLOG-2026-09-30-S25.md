**Bugs the tests exposed, fixed:**
1. `spec.riskTolerance` had no enum. `medium`, `Medium` or a typo was accepted, and `RiskAtOrBelow`
   read the unknown level as LOW (zero value of `riskOrder`), silently hiding every MEDIUM and
   HIGH upgrade. It now has the same enum as `autoplan.maxRisk`.
2. `spec.ai` was a value struct. `omitempty` never drops a struct, so a policy built in Go
   without it was sent with `ai: {provider: ""}` and rejected:
   `spec.ai.provider: Unsupported value: "": supported values: "anthropic", "ollama", "openai", "none"`.
   Any Go caller (the S35 UI endpoints, tests) was affected; YAML without `ai` was not. It is now
   `*AIProviderConfig`; nothing read the field.
3. A name repeated in `trackedTools` without a KB entry was listed once per repetition in
   `untrackableTools`, while known tools have been de-duplicated since S24. Both are listed once
   now.

### Errors Hit
1. **envtest can't stop its processes on Windows.** The first envtest run ended with
   `envtest: stop the API server: [unable to signal for process ...\kube-apiserver to stop: not
   supported by windows, unable to signal for process ...\etcd to stop: not supported by windows]`
   and left etcd (PID 4772) and kube-apiserver (PID 21788) running, plus a
   `k8s_test_framework_*` data dir. controller-runtime's `process.State.Stop` sends SIGTERM,
   which Windows can't deliver. The two processes were stopped and the dir removed. Fixed with
   `suite_windows_test.go`: it lists processes (Toolhelp snapshot) and kills `etcd.exe`/`kube-apiserver.exe` whose parent is the test binary, then
   waits for them.
2. **Stop race after the kill.** A forced start failure (CRD path pointed at a missing directory)
   showed envtest could still try to signal an already-killed kube-apiserver before noticing it
   exited. It then returns early and skips removing its auth dir. Fixed: `stopEnvtest` retries
   `env.Stop()` once after 500 ms when the processes were killed first. Re-checked: the forced
   failure run and three normal runs leave no processes and no temp dirs; the start failure
   still fails the run.
3. **setup-envtest and the toolchain.** `go run ...setup-envtest@...` runs outside the module,
   and this machine's base Go is 1.22.3, so it switched to a downloaded go1.26.8 (CI's setup-go
   1.26.2 needs no switch). The first `use` printed a stack trace and left its 51 MB download in
   `TMP`; it was removed, and later runs are clean.
4. **Line endings.** `make generate` showed `kubeviltrumite.io_stackupgrades.yaml` and
   `config/rbac/role.yaml` as modified by line endings only; restored. `gofmt -l` flags every CRLF
   working file, so formatting was checked by golangci-lint on the LF copy.
5. **Tests that failed on the old code, as intended:** `untrackableTools = [velero ingress-nginx
   velero]` (bug 3); `riskTolerance: medium` accepted (bug 1); every typed create rejected on
   `spec.ai.provider` (bug 2).

### Key Decisions
1. **Real scanners over a fake cluster, not stubs.** Both scanners read the same fake client
   (Flux and Argo CD objects as unstructured, workloads typed) and Helm comes from the injected
   lister. So the reconcile tests exercise `ScanAll`'s Flux/Helm merge, the workload rules and
   `resolveInstalled` together, as the operator runs them.
2. **The embedded knowledge base, with explicit expected versions.** Each test reads like the
   report it checks (`1.15.0` HIGH, `0.10.5` LOW). The cost: when S26 changes KB data, these
   expectations change with it.
3. **envtest behind `KUBEBUILDER_ASSETS`, in its own target and CI job.** `make verify` stays fast
   and offline. It still fails loudly: `make envtest` stops if setup-envtest fails, and
   `TestMain` fails the run if envtest was asked for but did not start.
4. **Pinned versions.** setup-envtest has no release tags, so it is pinned to the
   `release-0.23` head as a pseudo-version (controller-runtime v0.23). Kubernetes 1.35.0 matches
   `k8s.io/api` v0.35.
5. **Manifests for validation, the Go client for defaults.** The validation cases send
   unstructured objects, as `kubectl apply` does. The defaults case sends a typed object, as a Go
   caller does, which is how bug 2 surfaced: the fake client never validates.
6. **Validate `riskTolerance` in the CRD rather than normalize it in the controller.** One accepted
   spelling, the same as `maxRisk`; no case folding.
7. **Bugs fixed, design questions parked.** The three bugs above were fixed. The reconciler's
   message semantics, the autoplan fallback and scan-failure reporting are behaviour changes, so
   they became follow-ups (findings 5–7).
8. **Windows cleanup stays narrow.** Only `etcd.exe`/`kube-apiserver.exe` whose parent is the test
   binary are killed, never other processes, and `env.Stop()` is retried once.
