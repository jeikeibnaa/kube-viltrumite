### What Was Built
**Embedded knowledge base.** The six tool YAML files are compiled into the binary. `planner.Load`
takes any `fs.FS`: `knowledge.Tools()` in production, `os.DirFS(path)` when
`--knowledge-base-path` is set, `fstest.MapFS` in tests. It lists the directory with `fs.ReadDir`
rather than `fs.Glob`, because `Glob` swallows I/O errors — a wrong override path now fails with the
real "no such file or directory" instead of "no yaml files found". Only top-level `*.yaml` entries
are read. On startup the operator logs `knowledge base loaded source=embedded tools=6`.

**Operator image.** Three stages: `node:22-alpine` runs `npm ci && npm run build` in `ui/`;
`golang:1.26` builds `./cmd/operator` with `CGO_ENABLED=0 -trimpath -ldflags="-s -w"`; the runtime
is `gcr.io/distroless/static:nonroot` running as UID `65532:65532`, with `ui/dist` at `/ui` and
`ENTRYPOINT ["/operator", "--ui-path=/ui"]`. The build stages run on `$BUILDPLATFORM` and
cross-compile for `TARGETOS/TARGETARCH`, so the S48 multi-arch build needs no emulation.
`.dockerignore` is an allowlist (go.mod/go.sum, api, cmd, internal, knowledge, ui minus
node_modules/dist).

**Deploy manifests.** `kubectl apply -k config/default` (or `make deploy`) installs the CRDs, RBAC and
the Deployment into `viltrumite-system`. The Deployment runs with `--leader-elect`, one replica,
`runAsNonRoot`, `RuntimeDefault` seccomp, `readOnlyRootFilesystem`, no privilege escalation, all
capabilities dropped, `/healthz` and `/readyz` probes on `:8081`, requests 50m/128Mi, memory limit
512Mi. Because the root FS is read-only, an `emptyDir` is mounted at `/tmp` and `HOME=/tmp`, where
the Helm SDK and client-go's discovery cache write. The Namespace carries
`pod-security.kubernetes.io/enforce: restricted`, which this pod spec satisfies. `kubectl kustomize
config/default` renders: Namespace `viltrumite-system`; CRDs unprefixed;
`viltrumite-controller-manager` ServiceAccount and Deployment; `viltrumite-manager-role` ClusterRole
and Role; both bindings pointing at the prefixed ServiceAccount; image
`ghcr.io/jeikeibnaa/kube-viltrumite:dev`.

**RBAC.** The generated ClusterRole now covers what the operator actually calls: Flux
`helmreleases` and Argo `applications` (read through the unstructured client, which bypasses the
cache), Helm release `secrets` (listed by the Helm SDK's secret driver), and `events` (leader
election records core/v1 Events). Leases are a namespaced Role in `viltrumite-system`, generated from
a `namespace=` marker.

**UI server.** Three layers, all tested:
1. `--ui-bind-address` defaults to `127.0.0.1:8082`. In the pod the UI is not on the pod IP;
   `kubectl -n viltrumite-system port-forward deploy/viltrumite-controller-manager 8082` reaches it
   because port-forward dials the pod's loopback. Binding elsewhere logs a warning.
2. No CORS headers — the UI and API share one origin. `http.CrossOriginProtection` (Go 1.25+)
   rejects cross-origin writes with 403. This matters because the approve call is a POST without a
   body: browsers treat it as a "simple" request and send it cross-origin with no preflight, so
   removing `Access-Control-Allow-Origin: *` alone would not have stopped CSRF.
3. On a loopback bind, requests whose `Host` is not `localhost`/`127.0.0.1`/`[::1]` get 403. This
   blocks DNS rebinding, where a hostile domain re-resolves to 127.0.0.1 and becomes "same-origin".

The Vite dev proxy still works: the browser talks to `localhost:5173`, which is same-origin, and the
proxy forwards with `Host: localhost:5173`, which passes the Host check.

**Commits.** Four commits, each building on its own: server hardening, KB embed, RBAC markers,
deploy packaging. Commit 1 needed a server-only `cmd/operator/main.go` (the file also carries the KB
change); it was staged with `git hash-object` + `git update-index` and verified in a throwaway
worktree (`go vet`, `go test`, `go build` all pass).

### Key Decisions
1. **`planner.Load(fs.FS)` with `fs.ReadDir`**, not `fs.Glob`, so override-path errors surface.
2. **`--ui-bind-address` (host:port) replaces `--ui-port`**, matching `--metrics-bind-address` and
   `--health-probe-bind-address`. A breaking flag change, accepted before v0.1.0 (no users yet).
3. **UI stays on loopback in the pod** and is reached with port-forward. No `containerPort` is
   declared for it, so nothing suggests it is exposed. Auth arrives in S37.
4. **Stdlib `http.CrossOriginProtection`** instead of CSRF tokens: no UI change needed, and it covers
   the bodyless approve POST.
5. **Host check only on loopback binds.** Binding wider (e.g. behind an Ingress) is an explicit
   operator choice and would otherwise reject the Ingress hostname.
6. **Leases as a namespaced Role** — cluster-wide write on leases would let the operator disturb
   kube-controller-manager or scheduler leader election. Events stay cluster-wide because they are
   recorded next to the object.
7. **Kubebuilder layout: `system` placeholders + `namePrefix: viltrumite-`**, so the generic
   `manager-role` name cannot collide with other operators' ClusterRoles.
8. **Image tag `:dev` with `imagePullPolicy: IfNotPresent`** so `kind load docker-image` works
   before anything is pushed to ghcr.io.
9. **`HOME=/tmp` on an `emptyDir`** to keep `readOnlyRootFilesystem` without breaking the Helm SDK.
10. **Allowlist `.dockerignore`** — the context can never carry `.git`, `.claude` or local binaries.
11. **README left unchanged** — the in-cluster install steps go into the README in S22, once the kind
    smoke test has run them.

`kubectl kustomize config/default`-ийн гаралт: Namespace `viltrumite-system`; CRD-үүд prefix-гүй;
`viltrumite-controller-manager` ServiceAccount болон Deployment; `viltrumite-manager-role`
ClusterRole болон Role; хоёр binding хоёулаа prefix-тэй ServiceAccount-ийг заана; image
`ghcr.io/jeikeibnaa/kube-viltrumite:dev`.

**RBAC.** Үүсгэсэн ClusterRole одоо operator-ийн бодитоор дууддаг зүйлсийг хамарна: Flux
`helmreleases`, Argo `applications` (cache-ийг тойрдог unstructured client-ээр уншдаг), Helm
release-ийн `secrets` (Helm SDK-ийн secret driver жагсаадаг), `events` (leader election core/v1
Event бичдэг). Leases нь `namespace=` marker-аас үүссэн `viltrumite-system` дахь namespaced Role.

**UI сервер.** Гурван давхар хамгаалалт, бүгд тесттэй:
1. `--ui-bind-address`-ийн өгөгдмөл утга `127.0.0.1:8082`. Pod дотор UI нь pod-ийн IP дээр
   байхгүй; `kubectl -n viltrumite-system port-forward deploy/viltrumite-controller-manager 8082`
   нь pod-ийн loopback руу холбогддог тул хүрч чадна. Өөр хаяг дээр сонсвол анхааруулга log-д
   бичигдэнэ.
2. CORS header байхгүй — UI болон API нэг origin-той. `http.CrossOriginProtection` (Go 1.25+)
   cross-origin бичих хүсэлтийг 403-аар татгалзана. Энэ чухал, учир нь approve дуудлага нь body-гүй
   POST: browser үүнийг "simple" хүсэлт гэж үзэж, preflight-гүйгээр cross-origin илгээдэг. Тиймээс
   зөвхөн `Access-Control-Allow-Origin: *`-г хассан бол CSRF-ийг зогсоохгүй байсан.
3. Loopback дээр сонсож байхад `Host` нь `localhost`/`127.0.0.1`/`[::1]` биш хүсэлт 403 авна. Энэ
   нь DNS rebinding-ийг хаадаг: хортой домэйн 127.0.0.1 руу дахин resolve хийгдэж "same-origin"
   болох халдлага.

Vite dev proxy ажилласаар байна: browser `localhost:5173`-тай ярьдаг тул same-origin, proxy нь
`Host: localhost:5173`-аар дамжуулдаг тул Host шалгалтыг давна.

**Commit-ууд.** Тус бүр дангаараа build болдог дөрвөн commit: сервер хамгаалалт, KB embed, RBAC
marker, deploy багцлалт. 1-р commit-д зөвхөн серверийн өөрчлөлттэй `cmd/operator/main.go` хэрэгтэй
байсан (энэ файл KB-ийн өөрчлөлтийг бас агуулдаг); үүнийг `git hash-object` + `git update-index`-ээр
stage хийж, түр worktree дээр шалгасан (`go vet`, `go test`, `go build` бүгд амжилттай).

### Гарсан алдаа ба шийдэл
1. **Worktree хуучин commit дээр эхэлсэн.** Session-ий worktree `97342b1` (S20-оос өмнөх) дээр
   эхэлсэн. S20-ийн PR (jeikeibnaa/kube-viltrumite#1) merge хийгдсэн байсан тул branch-ийг

   урагшлуулсан. `main`-ийг worktree дотор checkout хийгээгүй (тэгвэл үндсэн checkout-оос түгжигдэх
   байсан).
2. **Heredoc нь Go string literal доторх `\n`-ийг жинхэнэ мөр шилжилт болгосон** (Python heredoc-оор
   бичихэд) → `string literal not terminated`. `toolYAML(name)` тестийн helper болон шууд засвараар
   шийдсэн.
3. **`undefined: err`** — Load-ийн давтагддаг кодыг `loadEmbedded(t)`-ээр сольсны дараа
   `TestResolve_UnknownTool`-д гарсан; `_, err = ...` → `_, err := ...`.
4. **`make generate` CRD болон deepcopy-г өөрчлөгдсөн мэт харуулсан** — зөвхөн мөрийн төгсгөл
   (`core.autocrlf=true`, generator LF бичдэг). `git diff --ignore-cr-at-eol` агуулгын өөрчлөлтгүй
   гэж харуулсан тул файлуудыг сэргээсэн. `gofmt -l` мөн CRLF-тэй бүх файлыг жагсаадаг тул CR-г
   хасаад шалгасан.
5. **Docker суугаагүй** (хэрэглэгч суулгахыг санал болгосон ч commit хийх үед байгаагүй).
   `docker build .` ажиллуулаагүй. Kube-context нь одоо resolve болохоо больсон
   `kubernetes.docker.internal`-ийг зааж байгаа тул `kubectl apply --dry-run=client` бас ажиллаагүй;
   оронд нь manifest-уудыг `kubectl kustomize`-ээр шалгасан.
6. **Code-reviewer script-ууд унасан** — Windows-ийн cp1252 console дээр emoji-гоос болж
   `UnicodeEncodeError`; `PYTHONIOENCODING=utf-8`-тэй ажиллавч stub (0 дүгнэлт) байсан. Review-г
   гараар хийсэн.

### Тестийн үр дүн
`make generate` амжилттай (exit 0); агуулгын хувьд зөвхөн `config/rbac/role.yaml` өөрчлөгдсөн.
`make verify` (vet + бүх unit test + build) амжилттай — бүрэн гаралтыг англи хэсгээс үзнэ үү. Шинэ
тестүүд бүгд давсан: мэдлэгийн сан ачаалах 5 тест (алдааны 5 тохиолдолтой) болон серверийн 5 тест
(CORS, preflight, cross-origin бичих, Host шалгалт, `isLoopback`). `make ui` амжилттай
(`index-*.js` 147.81 kB, gzip 47.74 kB). `kubectl kustomize config/default` 9 объект гаргасан.
`docker build .` — **Docker суугаагүй тул ажиллуулаагүй.** Cluster байхгүй тул юу ч deploy хийгээгүй;
kind smoke test нь S22-т.

### Гол шийдвэрүүд
1. **`fs.Glob` биш `fs.ReadDir`-тэй `planner.Load(fs.FS)`** — override замын алдаа ил гарна.
2. **`--ui-bind-address` (host:port) нь `--ui-port`-ийг сольсон** — `--metrics-bind-address`,
   `--health-probe-bind-address`-тэй нийцүүлсэн. Flag-ийн эвдэрсэн өөрчлөлт боловч v0.1.0-ээс өмнө
   (хэрэглэгч хараахан байхгүй) хүлээн зөвшөөрсөн.
3. **Pod дотор UI loopback дээр үлдэнэ**, port-forward-оор хүрнэ. Түүнд `containerPort` зарлаагүй
   тул ил гаргасан мэт харагдахгүй. Нэвтрэлт (auth) S37-д ирнэ.
4. **CSRF token биш stdlib-ийн `http.CrossOriginProtection`** — UI-г өөрчлөх шаардлагагүй, body-гүй
   approve POST-ийг хамарна.
5. **Host шалгалт зөвхөн loopback дээр.** Илүү өргөн хаяг дээр сонсох (жишээ нь Ingress-ийн ард)
   нь operator-ийн тодорхой сонголт бөгөөд үгүй бол Ingress-ийн hostname-ийг татгалзах байсан.
6. **Leases нь namespaced Role** — leases-д cluster даяар бичих эрх өгвөл operator
   kube-controller-manager эсвэл scheduler-ийн leader election-д саад учруулж чадна. Events нь
   объектынхоо дэргэд бичигддэг тул cluster даяар хэвээр.
7. **Kubebuilder-ийн бүтэц: `system` орлуулагч + `namePrefix: viltrumite-`** — ерөнхий
   `manager-role` нэр бусад operator-ийн ClusterRole-той давхцахгүй.
8. **`:dev` tag + `imagePullPolicy: IfNotPresent`** — ghcr.io руу юу ч push хийхээс өмнө
   `kind load docker-image` ажиллана.
9. **`emptyDir` дээрх `HOME=/tmp`** — Helm SDK-г эвдэлгүйгээр `readOnlyRootFilesystem`-ийг хадгална.
10. **Allowlist `.dockerignore`** — build context-д `.git`, `.claude`, локал binary хэзээ ч орохгүй.
11. **README-г өөрчлөөгүй** — cluster-т суулгах алхмуудыг kind smoke test баталгаажуулсны дараа S22-т
    README-д нэмнэ.
