## Key Decisions

1. **`client.Client` stored in `Server`, not `manager.Manager`** — `mgr.GetClient()` is called once in `NewServer`. This makes the struct testable with a fake client without implementing the large `manager.Manager` interface.

2. **Go 1.22 ServeMux** — method+path patterns (`GET /api/...`, `POST /api/.../approve`) handle routing without adding an external dependency. Gorilla Mux is in go.mod as an indirect dep but the spec required standard `net/http`.

3. **`ctx` extracted in main.go** — `ctrl.SetupSignalHandler()` is now stored as `ctx` so it can be shared between `uiServer.Start(ctx)` and `mgr.Start(ctx)`. Previously the context was ephemeral.

4. **Inline styles in App.tsx** — a single `<style>` block injected at render time avoids a separate CSS file dependency and keeps the React scaffold within the listed files.

5. **Vite 4 over Vite 6** — forced by Node 16 on the dev machine. Vite 4 supports Node ≥14.18/16. Upgrade path is available when Node is bumped.

## Code Review Findings

**[CRITICAL] Approve endpoint does not guard on current phase** (`server.go` `handleApproveStackUpgrade`)
— Patches `Phase=Approved` regardless of current phase. If the reconciler has already moved the resource to `Upgrading` or `Succeeded`, the approve reverts the phase and may re-trigger an upgrade loop. Fix: return 409 if `su.Status.Phase != UpgradePhasePending`.

**[CRITICAL] Wildcard CORS + no auth on mutating endpoint enables CSRF** (`server.go` `corsMiddleware`)
— `Access-Control-Allow-Origin: *` is applied globally including the `POST /approve` endpoint. No authentication or CSRF token. Any web page can trigger upgrade approval via a cross-origin POST when the port is reachable from a browser. Fix: scope allowed origin to `http://localhost:*` or add a required `Authorization` header.

**[CRITICAL] Approve button not guarded against concurrent clicks** (`App.tsx` `handleApprove`)
— No in-flight guard. A second click before the first POST resolves sends a concurrent approval. If the reconciler moved the resource to `Upgrading` between the two clicks, the second POST reverts Phase to `Approved`, stalling the controller. Fix: track approving rows in a `Set<string>` keyed by `ns/name` and disable the button while in-flight.
