### What Was Built
**Scanners report facts; the controller resolves them.** The scanner package still knows nothing
about the knowledge base. Each find carries the chart name, chart version, the app version when
the source knows it, evidence of the chart's origin, and the images it runs. The controller maps
it to a KB tool.

| Source | Name | App version | Chart version | Namespace |
|---|---|---|---|---|
| Flux `HelmRelease` (`v2`, else `v2beta2`, `v2beta1`) | `history.chartName`, else `spec.chart.spec.chart` | deployed `history.appVersion`; on v2beta1 from the Helm release it manages | deployed `history.chartVersion`, else `lastAppliedRevision`, else an exact spec version | release namespace (`history.namespace` / `targetNamespace`) |
| Helm (SDK) | `Chart.Metadata.Name` | `Chart.Metadata.AppVersion` | `Chart.Metadata.Version` | release namespace |
| Argo CD `Application` (`spec.source` or each `spec.sources` chart) | `chart` | from `status.summary.images` or the KB (in the controller) | `status.sync.revision(s)`, else an exact `targetRevision` | `spec.destination.namespace` |
| Raw (Deployment, StatefulSet, DaemonSet) | the detection rule's tool | image tag, cleaned | — | workload namespace |

- **Watched namespaces.** HelmReleases and Applications are listed cluster-wide and kept when they
  install into, or live in, a watched namespace. So a policy watching `external-secrets` still sees
  the HelmRelease in `flux-system` that manages it.
- **Flux runs Helm.** A release a HelmRelease manages is also a Helm release. `ScanAll` reports it
  once, as `fluxcd`, and fills what Flux lacks (the v2beta1 app version, the chart's home and
  sources) from the Helm release with the same namespace and name.
- **Identification (`resolveInstalled`).** A raw find is named by its rule. A chart goes through
  `Matrix.IdentifyChart`, which is `CanonicalName` plus `alias_origins`: istio's chart `base` counts
  only when its home, sources, Argo CD repoURL or Flux source name contains "istio". Otherwise it is
  listed under `unknownInstalled`; `istiod` alone identifies Istio. The app version comes from the
  source, else a known image (`VersionFromImages` with the tool's detection rules), else
  `Matrix.AppVersionForChart` (exact chart version only; no guessing between entries). One record
  per tool: GitOps (`fluxcd`, `argocd`) over `helm` over `raw`, then a comparable version.
- **Status messages.** An installed tool with no version gets "installed version unknown"; one with
  an unparsable version gets `installed version "latest" not recognised`. Neither claims "up to
  date".
- **`trackedTools`** accept aliases (`argocd`, `kube-prometheus-stack`) and are de-duplicated.
- **Raw detection.** Rules for all six tools, from the upstream manifests:

  | Tool | Workload | Image rule |
  |---|---|---|
  | argo-cd | `argocd-server` | `argoproj/argocd` |
  | cert-manager | `cert-manager` | `jetstack/cert-manager-controller` |
  | external-secrets | `external-secrets` | `external-secrets/external-secrets` |
  | istio | `istiod` (container `discovery`) | `istio/pilot` |
  | prometheus-stack | `prometheus-operator` | `prometheus-operator/prometheus-operator` |
  | vault | `vault` (StatefulSet) | `hashicorp/vault`, `hashicorp/vault-enterprise` |

  `image` matches the repository as a whole path suffix. So `argoproj/argocd` matches a mirror like
  `registry.local/quay.io/argoproj/argocd` but not `argoproj/argocd-image-updater`, and
  `hashicorp/vault` doesn't match the injector's `hashicorp/vault-k8s`. `CleanVersion` keeps
  `v1.15.0-rc.1` but turns `1.14.0-debian-12-r3`, `1.16.1-ent` and `1.22.0-distroless` into the
  release they are. A match whose tag is not a version (`latest`) gives way to a later one that is.
- **KB schema.** Detection `image_contains` became `image` (the meaning changed from substring to
  path suffix), and the new `alias_origins` is validated: keys must be aliases, with at least one
  word. `Load` also checks that a detection rule has a name or an image and that `version_from` is
  `image_tag` or `label`.

### Key Decisions
1. **Scanners stay KB-agnostic.** They report chart, versions, origins and images; the controller
   owns identification. The scanner package does not import the planner, and its tests need no
   KB.
2. **Precedence GitOps > Helm > raw.** The record names the source an upgrade has to go through. A
   Flux-managed release reported as `helm` would send S29 down the wrong path (audit #2).
3. **List GitOps objects cluster-wide, filter by watched namespace (release/destination or own).**
   Users list where tools run; Flux and Argo CD keep their objects elsewhere.
4. **`base` needs evidence (`alias_origins`), and failing the check is harmless.** An unconfirmed
   `base` shows as unknown, and Istio is still found through `istiod`. Checking origins for every
   chart would have broken mirrored and air-gapped repositories.
5. **App version order: source → known image → exact KB chart version.** No interpolation between
   KB entries: chart versions between two entries don't map to a known app line (for example,
   kube-prometheus-stack majors 46–47 are not in the KB).
6. **`image` replaces `image_contains`.** A path-suffix match is a different meaning, so it got a
   new name rather than a silent change; strict `Load` rejects the old key.
7. **Unknown versions are said out loud.** "installed version unknown" / "not recognised" replaces a
   false "up to date" (moved forward from S25 because the controller was being changed anyway).
8. **Injectable Helm lister.** Unit tests used to call the Helm SDK with the machine's current
   kube-context. Now they never can, and the Helm branch has tests.

  entry-үүдийн хооронд таамаглахгүй). Хэрэгсэл бүрт нэг бичлэг: GitOps (`fluxcd`, `argocd`) нь `helm`-ээс,
  `helm` нь `raw`-аас давуу, дараа нь харьцуулж болох хувилбартай нь.
- **Status мессежүүд.** Хувилбаргүй суулгасан хэрэгсэлд "installed version unknown", parse болохгүй
  хувилбартайд `installed version "latest" not recognised`. Аль нь ч "up to date" гэж хэлэхгүй.
- **`trackedTools`** alias (`argocd`, `kube-prometheus-stack`) хүлээн авч, давхардлыг арилгана.
- **Raw detection.** Upstream manifest-уудаас авсан зургаан хэрэгслийн дүрэм (хүснэгтийг англи хэсгээс
  үзнэ үү). `image` нь repository-г замын бүтэн төгсгөлөөр тааруулдаг: `argoproj/argocd` нь
  `registry.local/quay.io/argoproj/argocd` мэт mirror-т таарна, харин `argoproj/argocd-image-updater`-т
  таарахгүй; `hashicorp/vault` нь injector-ийн `hashicorp/vault-k8s`-д таарахгүй. `CleanVersion` нь
  `v1.15.0-rc.1`-ийг хадгалж, `1.14.0-debian-12-r3`, `1.16.1-ent`, `1.22.0-distroless`-ийг жинхэнэ
  хувилбар болгоно. Tag нь хувилбар биш (`latest`) таарал хожим олдсон жинхэнэ хувилбарт байраа тавьж
  өгнө.
- **KB schema.** Detection-ий `image_contains` нь `image` болсон (утга нь substring-ээс замын төгсгөл
  болж өөрчлөгдсөн). Шинэ `alias_origins`-ийг шалгадаг: түлхүүр нь alias байх, дор хаяж нэг үгтэй
  байх. `Load` мөн detection дүрэм нэр эсвэл image-тэй, `version_from` нь `image_tag` эсвэл `label`
  эсэхийг шалгана.

### Гол шийдвэрүүд
1. **Scanner-ууд KB-ээс хараат бус хэвээр.** Chart, хувилбар, гарал үүсэл, image-уудыг мэдээлнэ;
   тодорхойлолтыг controller хариуцна. Scanner package planner-ийг import хийхгүй, тестүүд нь KB шаардахгүй.

   удирддаг release `helm` гэж мэдээлэгдвэл S29 буруу замаар явна (аудит #2).

   өөрийнх).** Хэрэглэгч хэрэгсэл ажилладаг газраа жагсаадаг; Flux болон Argo CD объектуудаа өөр газар
   хадгалдаг.
4. **`base` нотолгоо шаардана (`alias_origins`), шалгалтад унах нь хор хөнөөлгүй.** Баталгаажаагүй
   `base` үл мэдэгдэх гэж харагдах бөгөөд Istio `istiod`-оор олдсоор байна. Бүх chart-ийн гарал үүслийг
   шалгавал mirror болон air-gapped repository-ууд эвдэрнэ.
5. **App хувилбарын дараалал: эх сурвалж → мэдэгдэх image → KB-ийн яг таарсан chart хувилбар.** KB-ийн
   entry-үүдийн хооронд интерполяц хийхгүй: хоёр entry-ийн хоорондох chart хувилбар мэдэгдэх app шугам
   руу буухгүй (жишээ нь kube-prometheus-stack-ийн 46–47 major KB-д байхгүй).
6. **`image` нь `image_contains`-ийг орлосон.** Замын төгсгөлөөр тааруулах нь өөр утга тул чимээгүй
   өөрчлөхийн оронд шинэ нэр авсан; хатуу `Load` хуучин түлхүүрийг татгалзана.
7. **Үл мэдэгдэх хувилбарыг ил хэлнэ.** "installed version unknown" / "not recognised" нь худал "up to
   date"-ийг орлосон (controller-ийг ямар ч байсан өөрчилж байсан тул S25-аас урагшлуулсан).
8. **Солих боломжтой Helm lister.** Unit тестүүд өмнө нь машины одоогийн kube-context-оор Helm SDK-г
   дууддаг байсан. Одоо хэзээ ч дуудахгүй бөгөөд Helm-ийн салбар тесттэй болсон.
