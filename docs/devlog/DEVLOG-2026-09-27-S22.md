**`make e2e`** (`hack/e2e.sh`) installs the operator the way a user would, then checks it:
1. `kind create cluster --name viltrumite-e2e --kubeconfig bin/e2e-kubeconfig --wait 120s`. The
   script exports `KUBECONFIG=bin/e2e-kubeconfig`, so the caller's kube-context is never switched.
   An existing `viltrumite-e2e` cluster is deleted first: re-loading the same `:dev` tag does not
   restart a running pod, so a kept cluster would test the old image.
2. `make docker-build` (skipped with `E2E_SKIP_BUILD=1`, after checking the image exists) →
   `kind load docker-image ghcr.io/jeikeibnaa/kube-viltrumite:dev` → `make deploy` →
   `kubectl rollout status` (180s).
3. Waits for the `CompatibilityPolicy` CRD to be `Established`, applies
   `config/samples/compatibilitypolicy_sample.yaml`, then
   `kubectl wait --for=jsonpath='{.status.mode}'=discovery` (the sample has no `trackedTools`) and
   checks that `.status.lastScanTime` is set. Prints each tracked tool's message.
4. The Lease `viltrumite-system/kube-viltrumite.kubeviltrumite.io` must be held by the controller
   pod (`holderIdentity` is `<pod name>_<uuid>`).
5. The pod log must not contain `forbidden` (an RBAC gap) or `read-only file system` (a write
   outside the `/tmp` emptyDir). `ERROR` lines are printed as warnings.
6. `kubectl port-forward pod/<pod> 8082:8082`, then `GET /api/health` must return
   `"status":"ok"`, and `GET /` must return the UI's `index.html`.

On failure it dumps pods, `describe` output, the last 200 log lines, the policy YAML and recent
events. The cluster is deleted at the end unless `KEEP_CLUSTER=1`.

### Key Decisions
1. **golangci-lint v2 `standard` plus gofmt/goimports, and nothing more.** The `std-error-handling`
   preset keeps the usual `defer resp.Body.Close()`. The version is pinned in two places (Makefile
   and workflow), each with a comment pointing at the other.
2. **`Requeue: true` gets a `nolint`, not a fix.** Removing it changes reconcile behaviour, and
   S27 owns that change.
3. **The e2e cluster has its own kubeconfig** in `bin/` (relative, because Git Bash rewrites
   absolute `/c/…` paths for Windows tools). A smoke test must never touch the user's clusters.
4. **Fresh cluster on every run**, so a kept cluster can't silently test a stale `:dev` image.
5. **Lease check on the Lease object**, not a grep of client-go's klog line: `holderIdentity`
   must start with the pod name.
6. **CI runs the same script as local.** `kind-action` only installs kind and kubectl
   (`install_only`); `hack/e2e.sh` creates and deletes the cluster.
7. **The e2e image is rebuilt from the image job's GHA cache with `load: true` and no
   attestations.** Attestation manifests make `kind load docker-image` fail on the containerd
   image store, which the local Docker Desktop (29.8.0) uses.
8. **Actions pinned to commit SHAs**, read-only token, `pull_request` (not `pull_request_target`):
   fork PRs get no secrets.
9. **The PR was opened as a draft before the docs.** At that point CI was the only Docker
   environment available. The docs followed once both CI and the local run passed.
10. **README install steps are the ones the smoke test runs**, so the README only claims what
    was tested.
11. **v0.1.0 is not tagged yet.** Tagging is outward-facing; it waits for the owner's go-ahead
    after the PR merges.
